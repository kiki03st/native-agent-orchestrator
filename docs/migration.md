# 기존 수동 훅에서 이전

이 저장소를 만드는 것만으로 기존 설치를 변경하지 않습니다. 기존 설치와 플러그인을 동시에 켜지 마세요.

1. 기존 세션에서 진행 중인 작업자를 모두 종료하고 결과를 정리합니다. 중단 상태의 예약이 있으면 먼저 실제 네이티브 상태와 대조합니다. 활성 실행을 플러그인으로 옮기지 않습니다.
2. Codex의 사용자 hooks.json과 Claude Code의 settings.json을 비공개 위치에 백업합니다. 백업을 저장소에 넣지 않습니다.
3. Codex에서는 기존 orchestration/hook.cjs를 실행하는 4개 그룹만 제거/비활성화합니다. Claude Code에서는 orchestration/claude-hook.cjs를 실행하는 6개 그룹만 제거합니다. Orca나 다른 플러그인의 훅은 유지합니다. 이 과정은 자동 실행하지 않습니다.
4. 플러그인을 설치하고 새 세션에서 로딩·신뢰를 확인합니다. 기존 `orch-*` 개인 작업자 파일은 남아 있어도 플러그인 작업자와 이름이 다릅니다. 필요하면 본인이 만든 해당 파일만 별도로 보관합니다.
5. 간단한 질문은 직접 응답하는지, 작은 읽기 전용 작업은 명시한 모델로 작업자가 만들어지고 결과가 검증되는지 확인합니다.

기존 DB는 원래 위치에 보관합니다. 새 플러그인은 기본적으로 새 데이터 위치를 쓰므로 예전 실행을 자동 재개하지 않습니다. 과거 기록을 계속 조회하려면 모든 실행이 종료된 상태에서 두 호스트의 `CODEX_ORCH_DB`를 기존 DB의 같은 절대 경로로 지정할 수 있습니다. 플러그인용 작업자 접두사가 바뀌었으므로 활성 Claude 실행을 이 방식으로 이전하지 마세요.

되돌릴 때는 새 플러그인을 비활성화하고 백업한 기존 훅만 복원한 뒤 새 세션을 시작합니다. 기록 파일은 제거하지 않습니다.
