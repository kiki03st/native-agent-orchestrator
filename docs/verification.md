# 검증 범위

개발 환경: Windows 및 WSL Ubuntu 24.04, Node.js 24.18.0, Codex CLI 0.154.0, Claude Code 2.1.270.

배포 전에 확인한 항목:

- 공통 엔진·수명 주기·Claude 어댑터 회귀 테스트.
- 두 개의 설치 사본이 설치 폴더 밖 공통 사용자 데이터 위치를 선택하는지 확인.
- 공백이 포함된 다른 임시 경로로 두 배포판을 복사한 뒤 실제 훅 명령을 실행하고, 예약 → 바인딩 → 결과 검증 → 종료 이벤트를 재현.
- Claude의 namespaced 작업자 선택, 실제 배포된 프로필 읽기, 중지 관측만으로 선행 단계가 종료되지 않는지 확인.
- Codex manifest 검증, Claude manifest/marketplace/18개 agent 정의 검증.
- 독립 코드 검토에서 지적한 Codex 추가 인자 허용을 거부하도록 보강하고 회귀 테스트로 검증.
- Ubuntu에서 POSIX 권한 문제를 수정 전 재현하고, 새 데이터 폴더 0700 및 DB/WAL/SHM 파일의 사용자 전용 접근을 수정 후 확인. Windows에서는 해당 POSIX 검사를 건너뜁니다.
- 빌드 결과와 공통 소스 일치 여부, Git 변경의 공백 오류, 배포 목록의 개인 경로·인증 파일·실행 기록 제외 여부.

이 테스트는 실제 모델 서비스를 호출하지 않습니다. 호스트가 훅을 로딩하고 실제 Agent/spawn_agent 호출을 이벤트로 전달하는지는 설치 대상의 새 세션에서 별도 확인해야 합니다. 특히 일부 래퍼 도구 경로는 네이티브 호출을 훅에 노출하지 않을 수 있습니다. `prepare` 이후 실제 호출에도 예약이 생성되지 않는다면 관리 위임이 활성화되었다고 간주하지 마세요. 해당 호출 경로로 계속 실행하지 말고 호스트 통합 상태를 확인해야 합니다.

이 저장소를 만들면서 기존 사용자 훅을 플러그인 설치로 교체하거나 새 플러그인을 중복 활성화하지 않았습니다. 따라서 배포 형식·재현 테스트 통과와 실제 사용자 환경으로의 이전 완료는 별개입니다. Linux/macOS는 GitHub Actions 결과를 확인하세요.

## 0.2.0 에서 추가로 확인한 것

- ORCH_TASK 마커가 없는 Agent/spawn_agent 호출이 PreToolUse·PostToolUse·PostToolUseFailure 어디서도 거부되거나 재조정 메시지를 내지 않는지 회귀 테스트로 확인.
- 마커가 있는 디스패치에 대해서는 프로필 무결성 검사, 준비된 인자 대조, 재귀 위임 거부가 종전대로 동작하는지 확인.
- Codex SubagentStart 의 무조건 worker 지침 주입을 제거하고, 계획된 작업자는 assignment message 로 같은 지침을 받는지 확인.

**미검증으로 남은 것:** Codex 훅이 PreToolUse 이벤트에 `agent_id` 를 싣는지 **실제 호스트에서 시험하지 않았습니다.** `src/hook.cjs` 의 재귀 위임 가드는 그 필드가 있을 때만 발화하므로, 싣지 않는다면 아무것도 막지 못합니다. Codex 작업자의 재귀 위임 차단을 보장으로 간주하기 전에 실제 Codex 세션에서 작업자가 자식을 스폰해 보고 거부되는지 확인해야 합니다. Claude 쪽은 `src/claude-hook.cjs` 의 동일한 가드가 실제 이벤트로 검증되어 있습니다.
